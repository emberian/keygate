# keygate hardening record

This file records the second and third hardening rounds: a 19-item second-order audit of the tree at `10342d5`, an eleven-point follow-up review (K-P1..K-P6), an independent six-item review of `9a3748d` (K-A1..K-A6), and seven additional findings from the third-round audit (C-1..C-7). Every item has a disposition and, where it was fixed, the code that fixes it and the test that would fail without the fix.

Dispositions: **fixed**, **already fixed** (before this round), **fixed differently** (the proposed remedy was replaced, with the reason), **declined in part** (with the reason).

## How the fixes were checked

All figures are from a Linux x86-64 build host (32 cores, rustc 1.99.1), debug build unless stated. Until W-4 below, the code had never been compiled or run on macOS.

| check | result |
|---|---|
| `cargo test --workspace` | 163 passed, 0 failed, 1 ignored (the benchmark) |
| of which | 73 `keygate-core` unit, 1 full-filesystem sandbox test, 24 `keygate-broker` unit, 35 + 19 + 6 broker integration, 5 CLI end-to-end |
| `cargo clippy --workspace --all-targets -- -D warnings` | clean |
| `cargo fmt --all -- --check` | clean |
| mutation checks (round 2) | 46 of 46 caught |
| independent reproducers inverted (round 3) | 6 of 6 caught before fixes, green after fixes |

**Mutation checks.** A test that passes proves little until it has been seen to fail. For 46 of the properties below, the fix was removed in a scratch copy (one at a time) and the named test was run; in every case it failed. The mutations cover the guard window, variants and retired patterns, the guard byte cap, gateway and socket pre-authentication bounds, the idle timeout, ticket ownership, stream expiry, the fixed provider endpoint, feature refusals, `best_of`, unpriced spend caps, token forwarding, `Idempotency-Key`, reply-header filtering, the own-uid rule, client broker identity, journal rollback (injected and on a real full filesystem), journal poisoning, shutdown, process dumpability, config and ancestor custody, the clock floor, the secret/guard pairing, audio output, the generation counter, three checks made between real kernel uids, and for K-P5 and K-P6: dropping `Uncertain` tickets at retention, ignoring the capacity bound, ignoring the seat floor, ignoring the owner's expiry, and evicting a retired secret on revocation.

**Real boundaries exercised.**

- *Full filesystem.* `crates/keygate-core/tests/enospc.rs` re-executes itself in a `bwrap` sandbox whose only writable filesystem is a 192 KiB tmpfs and fills it. Measured run: 799 audit lines, then 405 tickets, then `ENOSPC`; every failed append left both files parseable, nothing was charged for a refused reservation, the journal carried on once space returned, and it replayed after reopening.
- *Different kernel uids.* `scripts/multiuid-acceptance.sh` (run by the CLI test `tooth_real_multi_uid_separation`) enters a user namespace with subordinate uids mapped, builds a throwaway root on tmpfs, and runs the broker as uid 0 with callers as uids 1 and 2. Six checks pass: uid 1 is served with its scoped token; uid 1 cannot read the master key, sealed rows, journal, config or broker memory; uid 1 cannot mint, list, set, revoke or forget; uid 2 cannot use a token bound to uid 1; the broker's own uid is refused as a caller; and the operator's client sends nothing to a listener planted by uid 1.
- *Process memory.* The CLI test starts the real daemon and confirms from `/proc` that its `mem`, `environ` and `maps` cannot be opened by its own uid and that its core limit is 0, with an ordinary child process as the control.
- Skips are reported, not silent: both sandbox tests print `SKIPPED` with the reason when the host lacks `bwrap` or subordinate-uid mapping.

## Measurements

Design goals in SPEC.md are not measurements. These are:

| quantity | measured |
|---|---|
| cut notification, send to waiter ready (unit test, asserted) | under 100 µs |
| `revoke` call to the caller observing the stream end, 40 runs, debug build | min 359 µs, median 463 µs, max 793 µs |
| the same, asserted bound in the integration test | under 50 ms |
| guard build, 1 secret of 108 B (release) | 50 µs, 3 KiB of tables |
| guard build, 32 secrets of 108 B (release) | 1.5 ms, 96 KiB of tables |
| guard build at the 64 KiB pattern cap, 8 secrets of 8 KiB (release) | 17 ms, 1.7 MiB of tables |
| guard scan of SSE-shaped text, single core (release) | 42, 35 and 29 MiB/s for those three guards |
| shutdown drain with one stream and one hung call in flight | under 2 s (asserted), 0 unrecorded |

The earlier specification stated "<100 µs" for revocation as if it were the end-to-end figure. End to end it is a few hundred microseconds in a debug build; what is under 100 µs is the wake itself. The guard is the throughput limit for large streamed bodies: about 30–40 MiB/s per core, far above token streams and below a fast bulk download.

## Audit findings

**1. Crash retention of in-flight tickets (high).** *Already fixed* at `10342d5`: `Journal::open` demotes `InFlight` to `Uncertain` with `now + retention_s` (`journal.rs`, test `tooth_crash_recovery_uses_terminal_retention`). The shutdown half is *fixed* in this round: `Broker::shutdown` cuts every flight, waits up to `shutdown_grace_ms` for outcomes to be journaled and refuses new calls; `serve` calls it on SIGTERM/SIGINT. Test: `tooth_shutdown_cuts_flights_and_records_their_outcomes`.

**2. Journal write failures (high).** The compaction-reopen subclaim was *already fixed* (the compaction's own descriptor becomes the journal). *Fixed* here: `Inner::commit` tracks the committed length; a short write is cut back to it and only that operation fails; a failed cut-back, a failed `fdatasync`, or a failed directory sync after a compaction install poisons the journal, which then refuses every commit until restart. Memory is never ahead of disk. The audit log cuts back torn lines too. Tests: `tooth_short_write_is_rolled_back_and_the_journal_stays_bootable`, `tooth_unremovable_torn_record_poisons_the_journal`, `tooth_fsync_failure_poisons_and_memory_does_not_advance`, `tooth_compaction_directory_sync_failure_poisons`, `tooth_failed_compaction_before_install_changes_nothing`, the full-filesystem test above, and at the broker boundary `tooth_journal_failures_fail_closed_before_the_network`.

**3. Implicit operator and co-uid access (high).** *Fixed differently.* Peer-uid checks cannot protect a broker from its own uid, so the fix is a deployment boundary that is stated, checked and refuses ambiguity: `deployment = "separated"` is the default, requires `operator_uids`, does not serve a peer running as the broker's uid, requires HTTPS upstreams, and `serve` sets `PR_SET_DUMPABLE=0`, `RLIMIT_CORE=0` and umask 077 before any key is read, refusing to start otherwise (`harden.rs`, `Broker::may_call`). `development` keeps the old single-uid behaviour, by name, for tests. Tests: `tooth_separated_deployment_does_not_serve_the_brokers_own_uid`, `tooth_separated_deployment_refuses_implicit_operator_and_loopback_http`, `tooth_serve_hardens_the_process_and_checks_custody`, `tooth_default_init_boots_separated`, `tooth_real_multi_uid_separation`. Remaining and outside the program: creating the separate uid and a socket path callers can reach.

**4. Guard matched only the complete secret (medium-high).** *Fixed, with a different design.* The guard now trips on any 16 consecutive bytes of a secret or of a fixed set of re-encodings (percent-encoding in both hex cases, three JSON escapings), using one suffix automaton (`echo.rs`). *Declined in part:* ASCII case-folding is not done, because credentials are case-sensitive and folding matches unrelated text; no claim is made about base64, hex or other transformations, and the limits are tested so they stay documented. Tests: `tooth_truncated_and_altered_echoes_trip`, `tooth_encoded_variants_trip`, `tooth_matches_the_naive_definition` (a differential test against the definition written the slow way), `tooth_truncated_altered_and_encoded_echoes_are_withheld`.

**5. Rotated and revoked secrets no longer scrubbed (medium).** *Fixed.* Previous secrets are kept sealed in the row file (seal format 2, format 1 still readable) as guard-only patterns until `keygate forget`; at most 8 beside an active secret, 9 on a revoked row (see K-P6). Tests: `tooth_retired_secrets_stay_guarded_until_forgotten`, `retired_secrets_round_trip_and_format_1_still_opens`, `tooth_cli_retire_forget_and_broker_identity`.

**6. Guard memory, reallocation and lock hold (medium).** *Fixed.* Tables are sparse (1.7 MiB at the cap, against 256 MiB before), allocated once at final size and zeroed on drop; total pattern bytes are capped at 64 KiB and a `set` over the cap is refused; the holdback is a fixed 16-byte array; the automaton is built outside any lock a request takes. Tests: `tooth_guard_size_is_bounded`, `tooth_guard_budget_is_enforced_at_set`.

**7. Buffering before authentication, no read deadlines (medium).** *Fixed.* Gateway: the token and route are verified from the request head (`Broker::preauthorize`), the body is limited to what that token may send to that row and refused from `Content-Length` alone, and head and body have a deadline. Socket: 64 KiB frame limit until a token is `present`ed, incremental allocation, frame and idle deadlines, bounded read-ahead. Tests: `tooth_gateway_authenticates_and_bounds_before_reading_the_body`, `tooth_unix_frames_are_bounded_before_authentication`, `tooth_frames_are_bounded_before_they_are_buffered`. What remains bounded rather than eliminated: authenticated peers can together hold `max_connections` times a row's `max_request_bytes`.

**8. Budgets.** (a) *Fixed:* a cap on a row with no prices is a config error; a spend-capped token is refused on an unpriced provider row. (b) *Fixed:* server-held input, fetched input, provider-run tools, premium tiers and inline media are refused unless the row's `allow` lists them; the reservation is now an upper bound for text-only requests (one token per body byte plus 4096, at the dearest input price including cache writes). Settlement still records actual usage even above a reservation, which is truthful accounting and is documented. (c) *Fixed:* `best_of` multiplies like `n`. (d) *Fixed by refusal:* `previous_response_id` and the like need `server-state`; with it allowed, cross-seat reference is possible and documented, since stored objects belong to the upstream key. Tests: `tooth_caps_without_prices_are_refused`, `tooth_unmetered_and_server_side_input_is_refused_unless_allowed`, `tooth_reservation_covers_choices_cache_prices_and_null_fields`, `tooth_cache_and_stream_usage_settle_exactly`.

**9. Path-selected models bypass the allowlist (medium).** *Fixed.* A provider row has a `dialect` and accepts `POST` at exactly one endpoint whose body carries the model; Gemini-native, Bedrock and Azure deployment paths cannot be configured. Test: `tooth_provider_rows_reach_one_endpoint_of_their_dialect`.

**10. Tickets shared between tokens of one seat (medium).** *Fixed.* The request digest includes an owner id derived from the verified final tag, and the sorted spend scopes. Tests: `tooth_tickets_belong_to_the_token_that_opened_them`, `tooth_owner_id_is_per_token_and_hides_the_tag`.

**11. Streams outlive token expiry (medium).** *Fixed.* The relay waits on a timer for the token's earliest expiry and closes with `closed_by: expired`. Tests: `tooth_stream_is_cut_when_its_token_expires`, `tooth_cut_watch_expires_on_the_token_deadline`.

**12. Loopback HTTP upstreams and port squatting (medium).** *Fixed differently.* Checking the listener's uid or restricting ports would not make an unauthenticated transport safe, and removing it would break local fixtures. Plain-HTTP loopback is now an explicit development transport: accepted only with `deployment = "development"`, refused with a message that says why otherwise. Test: `tooth_separated_deployment_refuses_implicit_operator_and_loopback_http`.

**13. Dangerous headers not reserved (low-medium).** *Fixed.* Method-override, URL-rewrite and forwarding headers cannot be configured at all; credential headers cannot be opened to callers; billing-identity headers can be fixed by the operator but not sent by callers. Test: `tooth_dangerous_headers_cannot_be_configured`.

**14. Tokens in the query forwarded (low-medium).** *Fixed, and declined in part.* A request whose query or forwarded headers contain a keygate token, or whose body contains the presented token, is refused; `x-goog-api-key` is accepted as a token source and stripped. A token in the query is *not* accepted as authentication, because URLs are logged. Test: `tooth_tokens_never_travel_upstream`.

**15. `Idempotency-Key` consumed, never forwarded (low).** *Fixed.* It is used for deduplication and forwarded where the row lists it. Test: `tooth_idempotency_key_is_forwarded_where_allowed`.

**16. Upstream can spoof `x-keygate-*` and pass hop-by-hop headers (low).** *Fixed.* Test: `tooth_upstream_cannot_spoof_keygate_or_hop_by_hop_headers`.

**17. `null` handled inconsistently (low).** *Fixed.* An explicit `null` is absent everywhere, and one function decides whether a body asks for a stream. Test: `tooth_reservation_covers_choices_cache_prices_and_null_fields`.

**18. Root path.** *Already fixed* at `10342d5` (`/` is the zero-segment path; `path.rs` tests).

**19. Bind window, unverified server, clock fail-open, config custody (low).** *Fixed.* The socket is bound under a private name, given its mode, then renamed into place. The client verifies the listener from kernel peer credentials before sending. A clock before the epoch or before 2025-06-15 is an error (`clock_failed`), never zero. The config must be a regular file owned by the broker or root and not writable by others. Tests: `tooth_client_verifies_the_broker_and_socket_mode_is_never_wider`, `tooth_client_refuses_an_unexpected_listener`, `tooth_broken_clocks_fail_closed`, `tooth_config_custody`.

The audit also noted that it found no upstream request smuggling; nothing in this round changes the properties that note rested on.

## Follow-up review findings

**K-P1. A flight could be paired with a guard that no longer contained its secret.** *Confirmed and fixed.* `snapshot` read the secret, then separately the guard; `set --forget-retired` (and `revoke --forget`) could publish a guard without the old secret in between. The pair is now read under the guard lock and published under it, held only across pointer reads and writes, never across sealing, `fsync` or a build. Test: `tooth_snapshot_pairs_the_secret_with_a_guard_that_contains_it` pauses a reader at exactly that point and shows the writer waits.

**K-P2. Only the state directory itself was checked.** *Confirmed and fixed.* Every ancestor must be owned by the broker or root and not writable by others (sticky excepted); the broker uses the canonical path it checked; the config is held to the same rule. Custody opens no longer follow symlinks, block on FIFOs, accept non-regular files or read without a bound. Tests: `tooth_untrusted_ancestors_are_refused` (which also checks no mode is altered), `tooth_fifo_config_does_not_block`. The check is by path at startup, not by directory descriptor; it relies on the checked ancestors staying trusted, which their ownership and modes ensure.

**K-P3. The client trusted a socket whose owner and listener agreed.** *Confirmed and fixed.* Without an explicit broker uid the client now trusts only a listener that is root or itself, and checks the whole path to the socket. Tests: `tooth_client_checks_the_whole_path_to_the_socket`, and the planted-listener check in the multi-uid script, where a listener bound by uid 1 receives no bytes from the operator's `set`.

**K-P4. Audio output and stored audio ids were not recognised.** *Confirmed and fixed.* `modalities` other than text and Chat Completions `audio` need a new allowance, `non-text-output`; an assistant message's `audio.id` needs `server-state`. No pricing for audio is implemented: with the allowance, the row's caps are not bounds, as for the other allowances. Test: `tooth_unmetered_and_server_side_input_is_refused_unless_allowed` (no upstream connection is made for any refused request).

**K-P5. `Uncertain` tickets were forgotten at `retention_s`.** *Confirmed and fixed.* The journal dropped an `Uncertain` ticket at the same deadline as a completed reply, so an exact retry (same token, same `Idempotency-Key`, same bytes) arriving later opened a fresh ticket and re-sent a request whose first attempt may have landed. Raising crash retention had only moved the deadline. Now a ticket records its token's expiry and seat epoch, and an `Uncertain` ticket is forgettable only after `retention_s` *and* once that token can no longer retry: its expiry has passed, or its seat's revocation floor, journaled as its own record and reconciled with the seat file at start, is above its epoch. The ledger of such tickets is capped (`max_uncertain_tickets`, default 10000); at the cap new requests are refused with `no_resend_ledger_full` and nothing is evicted. Completed replies keep their finite window, which is now documented as such: after it, an identical request is a new request. A new request id is the caller deliberately sending again and is unaffected. Tests: `tooth_uncertain_requests_are_never_resent_however_late_the_retry` (through the HTTP gateway: retry after retention, after a restart, at capacity, and after seat revocation, counting upstream hits), `tooth_uncertain_tickets_outlive_retention_while_their_owner_can_retry`, `tooth_uncertain_capacity_fails_closed`. What this does not do: it does not keep completed replies longer, and a token with no expiry on a never-revoked seat keeps its `Uncertain` records forever, which is what the cap is for.

**K-P6. Revocation at capacity forgot the oldest retired secret.** *Confirmed and fixed.* `revoke` on a row with 8 retired secrets dropped the oldest to make room for the one being revoked, so a still-valid old key stopped being withheld without anyone asking. A revoked row has no active secret, so it holds exactly the secrets it held before; it is now allowed that ninth retired slot (the seal format accepts 9 only when there is no active secret), revocation never evicts and is still never refused, and total stored and guarded bytes per row are unchanged by it. A new `set` on such a row is refused until `forget`. Only `forget`, `set --forget-retired` and `revoke --forget` remove patterns. One exception is reported rather than silent: if the tombstone cannot be written, the sealed file is removed so the revoked secret cannot return at restart, and the error says the sealed copy of the retired secrets went with it (they stay guarded in memory until restart). Tests: `tooth_revocation_at_capacity_forgets_nothing` (every one of nine keys still withheld on another row, before and after a restart, until `forget`), `retired_secrets_round_trip_and_format_1_still_opens`.

**Counter bounds.** *Fixed.* A row's generation counter is checked and fails closed one short of its maximum, so a revocation floor can always exceed it; the in-flight count saturates. Seat epochs were already checked. Test: `tooth_generation_counter_does_not_wrap`.

**Multi-uid acceptance.** The earlier note in this round that real multi-uid behaviour could not be exercised without root was wrong. It is exercised, as described above.

The other seven points of that review concern a different project and have no disposition here.

## Independent review and third-round audit findings

**K-A1. OpenAI Responses `input` item references with omitted or `null` `type` bypassed `server-state`.** *Confirmed and fixed.* OpenAI's `ItemReference` schema defaults `type` to `"item_reference"` when omitted or `null`, so `{"id": "msg_..."}` and `{"id": "msg_...", "type": null}` dereferenced stored context without opting into `allow = ["server-state"]`. `responses_input_items` (`provider.rs`) now classifies the direct `input` union boundary: untyped/null-typed items carrying `id` and contentless `"message"` items carrying `id` require `server-state`, while non-object items, non-array/string `input`, and non-string discriminators (`"type": false` / `0`) fail with `bad_request`; `content_part` also classifies `computer_screenshot` outputs (`file_id`, remote `image_url`, or inline screenshot data). Ordinary untyped `EasyInputMessage` items, inline `OutputMessage` history items, `function_call` / `function_call_output` items, and arbitrary `id` properties inside tool schemas or arguments are unaffected. Test: `tooth_responses_item_references_require_server_state_without_blocking_tool_ids`.

**K-A2. Terminal `response.incomplete` SSE usage was ignored.** *Confirmed and fixed.* Hitting `max_output_tokens` on an OpenAI Responses stream ends cleanly with `response.incomplete` carrying complete `response.usage`; ignoring it left tickets charged at their conservative reservation. `UsageSniffer::event` (`provider.rs`) now extracts usage from a single terminal `response.completed` or `response.incomplete`, requires complete `input_tokens` and `output_tokens` on those terminal events, ignores non-terminal `response.*` events (`response.in_progress`), invalidates settlement if any JSON event arrives after a terminal `response.*` event or if `message_start` repeats, treats `response.failed` / `response.cancelled` as invalidating usage, and ignores `"error": null`. Tests: `tooth_incomplete_response_stream_settles_complete_usage_and_keeps_bad_usage`, `tooth_usage_sniffer_bounds_and_partial_events`.

**K-A3. No lifetime exclusive state-directory lock (`broker.lock`).** *Confirmed and fixed.* Two brokers pointed at the same state directory with different sockets could split daily budgets and bypass revocation, and even a duplicate startup on the *same* socket ran `Journal::open` recovery and compaction (replacing `journal.wal`'s inode) before failing socket bind, stranding acknowledged replies written to the running broker's unlinked descriptor. `StateLock::acquire` (`harden.rs`) acquires a nonblocking exclusive `flock` on `<state>/broker.lock` (`0600`, singly linked regular file, `O_NOFOLLOW`) inside `Broker::open` and `Broker::init_state` before any custody read, recovery, or compaction, and `Inner` holds `_state_lock` as its last-dropped field across all `Broker` clones and active flights. Tests: `tooth_state_lock_is_exclusive_and_validates_custody`, `tooth_state_lock_blocks_second_broker_on_any_socket`, `tooth_failed_duplicate_start_preserves_retained_reply_durability`, and duplicate `serve`/`init` checks in `tooth_serve_hardens_the_process_and_checks_custody`.

**K-A4. `AuditLog` reopen concatenated onto crash-torn final lines and lacked writer poisoning.** *Confirmed and fixed.* `AuditLog::open` (`audit.rs`) and `Journal::open` (`journal.rs`) validate every newline-terminated JSON record from byte 0 (refusing complete malformed records mid-file or at EOF), truncate and sync only an unterminated final record left by a crash mid-append before accepting new writes, and `AuditLog` rolls back short writes (`ftruncate` + `fdatasync`) and poisons the writer on failed rollback or failed `fdatasync` so no `Begin` can be acknowledged with uncertain audit durability until restart. Tests: `tooth_audit_torn_tail_recovery_poisoning_and_parent_sync`, `tooth_audit_recovers_torn_tail_and_poisons_broker_on_failed_sync`, `torn_tail_is_cut_and_mid_file_damage_is_an_error`, `tooth_real_enospc_leaves_journal_and_audit_log_whole`.

**K-A5. Durable delays after admission extended stream expiry countdowns.** *Confirmed and fixed.* `Broker::prepare` (`engine.rs`) now binds the token's monotonic `expires_at` deadline against the sub-second wall clock at admission; `Broker::begin` fails closed before claiming a ticket or auditing `Begin` when that deadline has already elapsed, and `CutWatch::cut` checks `Instant::now() >= at` synchronously on its first poll before entering `sleep_until`. Tests: `tooth_begin_and_cut_watch_do_not_restart_expiry_after_admission_delay`, `tooth_expired_stream_never_contacts_upstream`.

**K-A6. Initial `audit.log` and namespace directory creation omitted parent-directory `fsync`.** *Confirmed and fixed.* `AuditLog::open` syncs `audit.log`'s parent directory, `SealStore::write` creates `0700` non-symlink namespace directories (`providers/`, `services/`) and syncs the state root (`sync_parent(dir)`) before `write_atomic`, `Broker::init_state` creates missing intermediate state directories via `create_dir_all_0700_synced` (syncing every newly created directory entry up to and including the deepest pre-existing ancestor), `keygate init` syncs `keygate.toml` and its parent, and `sync_parent` handles relative single-component paths (`"."`). Directory-entry durability is verified by boundary `fsync` ordering and fault-injection probes, not by a physical power-cut rig. Tests: `tooth_namespace_creation_syncs_state_root_and_refuses_symlinks`, `tooth_audit_torn_tail_recovery_poisoning_and_parent_sync`.

**C-1 through C-7 (third-round audit follow-ups).** *Fixed.*
- *C-1 (`seal.rs`):* `SealStore::seal` wraps its pre-allocated plaintext buffer in `Zeroizing` so an early CSPRNG error before in-place encryption still wipes active and retired secrets on drop.
- *C-2 (`journal.rs`, `harden.rs`, `engine.rs`):* `Journal::open` refuses `journal.wal` with group/other permission bits (`mode & 0o077 != 0`); automatic compaction propagating a directory-sync poison fails the triggering commit closed; `seats.json` is read via `harden::read_state_file` (`O_NOFOLLOW | O_NONBLOCK`, regular `0600` file owned by the broker, 16 MiB cap). Test: `journal_file_is_0600`.
- *C-3 (`unix.rs`):* Unix socket `set`, `revoke`, `forget`, `revoke-seat`, and `status` check `is_operator` before acquiring a bounded `disk_slots` blocking-pool permit (after zeroizing `secret_b64`), and pipelined read-ahead zeroes old buffers on growth. Test: `tooth_non_operator_requests_do_not_consume_disk_pool`.
- *C-4 (`unix.rs`, `lib.rs`):* `unix::bind` probes an existing socket file with a nonblocking `AF_UNIX` `SOCK_STREAM` (`SOCK_NONBLOCK | SOCK_CLOEXEC`) and replaces it only on `ECONNREFUSED` / `ENOENT` (so a live listener with a full backlog returns `AddrInUse` immediately without blocking in `connect(2)`), and `Listeners::bind` removes the newly bound Unix socket if `gateway::bind` fails. Test: `tooth_bind_probes_full_backlog_socket_without_blocking`.
- *C-5 (`provider.rs`):* Covered under K-A1 and K-A2 above (strict `input` union type checks, `computer_screenshot` outputs, single-terminal `response.*` and `message_start` invariants, `"error": null` handling).
- *C-6 (`main.rs`, `cli.rs`, `multiuid-acceptance.sh`):* CLI token-file buffers move directly into `String::from_utf8` without cloning and zeroize `FromUtf8Error::into_bytes` on invalid UTF-8; serialized wire frames use `Zeroizing` across async writes; and every spawned test child/daemon uses a drop guard (`kill` + `wait`) so panics or early refusals never leak background processes.
- *C-7 (`engine.rs`, `gateway.rs`, `unix.rs`):* Spawned transport connection loops hold `WeakBroker` while idle, release strong `Broker` before writing Unix socket response frames, bound Unix socket frame writes with the frame deadline plus listener-stop/shutdown cancellation, and initiate immediate shutdown (`graceful_shutdown` on HTTP/1.1 keep-alive; `select!` wakeup on idle Unix socket reads) when a listener stops or `Broker::shutdown` fires, so idle or stalled peers neither pin decrypted secrets in memory nor retain `broker.lock` after active flights finish. Test: `tooth_stalled_hello_pipelining_does_not_pin_broker_or_state_lock`.

## What is still not true

- keygate does not create the OS boundary it depends on. A broker run as the same uid as its callers, in `development` mode, protects nothing from them.
- The response guard does not catch fewer than 16 consecutive bytes, base64, hex, case changes, or any transformation outside its variant list.
- With any `allow` entry on a provider row, reservations for requests using that feature are not upper bounds.
- Reservations assume the row's configured prices are the highest that apply, and at most 4096 tokens of provider-added prompt.
- Completed requests are deduplicated for `retention_s` only. After it, an identical request with the same `Idempotency-Key` is sent again; only requests of unknown outcome are remembered for the life of their token.
- A token with no expiry on a seat that is never revoked accumulates `Uncertain` records until `max_uncertain_tickets`, at which point the broker refuses new requests until a seat is revoked. Mint tokens with an expiry.
- Custody checks happen at startup, by path. An administrator who later loosens an ancestor's permissions is not detected until restart.
- Directory-entry `fsync` ordering is covered by boundary instrumentation and fault injection, not by physical power-loss testing.
- The gateway has no peer credentials; any local process holding a valid token can use it there.
- Separated deployment is supported on Linux only.


## Worker dispatch and disk latency, 2026-11-23

The 2 ms real-disk target remains open. These are end-to-end medians in milliseconds from the release worker acceptance harness. Each run used 64 sequential dispatches, 64 independent claims, 64 completions using the returned tokens and 16 fresh authoritative Git reconciliations. The settled-ticket replay has its own timing.

| State and Git storage | Dispatch | Pod claim | Pod done | Git reconcile |
|---|---:|---:|---:|---:|
| Linux tmpfs, colocated | 0.365 | 0.925 | 0.934 | 1.000 |
| Linux ext4, colocated | 0.300 | 4.414 | 4.858 | 2.216 |
| Linux tmpfs, sandboxed worker in local KVM guest | 2.801 | 6.035 | 5.927 | 6.635 |
| Linux ext4, sandboxed worker in local KVM guest | 2.746 | 17.665 | 17.451 | 11.785 |
| macOS APFS shared over VirtioFS with a Linux guest | 0.934 | 4.229 | 3.819 | 6.176 |

The KVM runs kept the broker, pod service, destination repository and timer on the host. A private SSH Unix-socket forward connected the worker to the broker. Three Git land fixture calls timed out on ext4. In the APFS run the guest ran the x86-64 Rust executables through Rosetta, used native Linux Node, and placed only the broker socket on guest tmpfs. Two Git land fixture calls timed out. The harness retained first-attempt timings and failed the timeout gate after reporting the medians.

A separate 128-write ext4 control on the KVM host measured 3.07 ms median for one 500-byte append and `fdatasync`. Immediate pod calls still require a durable in-flight ticket, an independently synced pre-send audit entry, and a durable outcome before acknowledgement. For a colocated run, place the release binaries on `PATH`, set `TMPDIR` to a private directory on the filesystem being measured, and run `python3 scripts/worker-acceptance.py`. Use `--socket-dir` when the data filesystem cannot host the broker's Unix socket.

## Worker toolchain and grant, 2026-11-24

A readiness review found that `keygate-worker` started its jail from fixed Linux tool paths it never checked (W-1), and a reading of the worker found its macaroon wider than its grant (W-2). Running the worker on current Node found W-3, and building on macOS for the first time found W-4.

| check | macOS (arm64, rustc 1.98.0-nightly) | Linux (x86-64, Ubuntu 24.10, rustc 1.100.0-nightly) |
|---|---|---|
| `cargo fmt --all -- --check` | clean | clean |
| `cargo clippy --workspace --all-targets -- -D warnings` | clean | clean |
| `cargo test -p keygate --bin keygate-worker` | 9 passed | 9 passed |
| `cargo test -p keygate --test worker` | 3 passed (the Linux tests are not built) | 7 passed |
| `node --test scripts/worker-context.test.cjs` | 2 passed (Node 26.13.0) | 2 passed (Node 24.22.3) |
| `bind_keeps_existing_socket_where_busy_and_stale_look_alike` | passed | not built (Linux keeps the probe) |
| `cargo test --workspace` | not run | 185 passed, 0 failed, 1 ignored (the benchmark) |
| mutation checks | 1 of 1 caught | 16 of 16 caught |

The Linux host lets only profiled binaries create user namespaces (`kernel.apparmor_restrict_unprivileged_userns=1`), so the jail ran under a copy of Bubblewrap 0.10.0 with an AppArmor `userns` profile, named with `--bwrap-bin`, and under the official Node v24.22.3 build checked against its published SHA-256. The host's own Node 20.16 is the one `tooth_check_toolchain_only_refuses_a_node_without_dont_contextify` refuses. In the workspace run, `tooth_real_enospc_leaves_journal_and_audit_log_whole` used the system bwrap and reported `SKIPPED`; with the profiled copy first on `PATH` it passed (390 tickets and 799 audit lines; every failure clean). `tooth_real_multi_uid_separation` reported `SKIPPED` because the host maps no subordinate uids.

**Mutation checks.** Each fix was removed in turn from a copy of the tree and the tests named for it were run; every removal failed at least one of them. Removed: the row narrowing, the path narrowing, the supervisor's grant check, the spelling check, the file-mode, execute-bit, directory-mode and owner checks, the pin comparison, the check before each restart, the full `lstat` identity (keeping only device and inode), the library-directory guard, each of the two `context.cjs` refusals, the background runtime shutdown, and the caveat order; on macOS, replacing an existing socket without a probe.

**W-1. The worker ran whatever its fixed toolchain paths held.** *Confirmed and fixed.* The supervisor executed `/usr/bin/prlimit`, which executed `/usr/bin/bwrap`, which executed `/usr/bin/node`, without looking at any of them, before every start and every restart. `--prlimit-bin`, `--bwrap-bin` and `--node-bin` now name each binary by absolute path (the defaults are unchanged). A relative path or one with `..` is refused by its spelling before anything is looked up, and `PATH` is never consulted. `VerifiedToolchain::verify` resolves each path and requires a regular file with an execute bit, owned by root or the worker's uid, writable by neither group nor others, in a directory writable by neither (sticky or not), below directories `check_trusted_dirs` accepts. `--prlimit-sha256`, `--bwrap-sha256` and `--node-sha256` pins are compared with a digest read through one descriptor whose `fstat` matches the checked file before and after the read. Workers run only the canonical paths, and Node is bound into the sandbox at its own canonical path. `--node-lib-dir` binds a further directory under the same rules, and is refused if it holds the token file or the broker socket. Before every worker start in a pool, each binary's `lstat` identity (device, inode, size, mode, owner, modification and change times) must equal the verified one. On any difference the pool answers that job with `"reason":"toolchain"` and exits with an error instead of running a file it did not verify; its runtime shuts down without waiting for the blocking read of standard input, so it exits even while its caller holds the pipe open. `--check-toolchain-only` verifies the toolchain, starts one sandboxed worker, prints canonical paths and SHA-256 digests as JSON and exits without reading a token. Tests: `toolchain_paths_are_judged_by_spelling_before_any_lookup`, `toolchain_binaries_are_regular_executables_only_their_owner_can_change`, `a_pinned_binary_must_match_its_sha256`, `recheck_notices_a_rewritten_replaced_or_rechmodded_binary`, `library_directories_are_held_to_the_same_custody`, and in `crates/keygate/tests/worker.rs` `tooth_relative_or_climbing_toolchain_paths_are_refused_before_any_lookup`, `tooth_writable_or_mispinned_toolchain_is_refused`, `tooth_library_directory_may_not_expose_the_token_or_the_socket`, and on Linux `tooth_check_toolchain_only_reports_digests_that_pin_the_real_toolchain` and `tooth_pool_stops_instead_of_restarting_a_replaced_binary` (it replaces the pool's Node with an identical copy under a live pool).

**W-2. Every pool's macaroon admitted every worker operation.** *Confirmed and fixed.* Whatever `--allow` said, the supervisor narrowed its token to both rows and all three paths, so the only thing keeping a `pod.claim` pool from `/pod/done` and `/git/land` was the supervisor's own check; the token itself would have been admitted for both. `Grant` now derives `Rows` and `PathPrefixes` from the allowed operations alone. `git.reconcile` needs exactly what `git.land` does, because `reconcile_git_push` admits the original land call again before it probes the ref. `--pod-row` and `--git-row` are required only when an allowed operation uses them, and a row no allowed operation uses is not granted. Lists follow a fixed operation order, so equal options give byte-identical tokens however `--allow` is written, which matters because tickets belong to the exact token that opened them. Granting all four operations reproduces the earlier caveats exactly. The supervisor's own check now consults the same `Grant`. Tests: `tooth_pod_claim_token_is_refused_for_pod_done_and_git_land` (the real broker admits all three calls under the full grant, admits only the claim under `pod.claim`, still refuses after the holder appends wider `Rows` and `PathPrefixes`, and answers `bad_token` for the full caveat chain under the claim-only tag), `grant_admits_only_the_rows_and_paths_its_operations_use`, `grant_needs_and_holds_only_the_rows_its_operations_use`, `equal_grants_make_equal_tokens_and_the_full_grant_keeps_its_token`, and on Linux `tooth_pool_runs_handlers_in_the_jail_and_holds_only_its_grant`. A pool granted fewer than all four operations now holds a different token than before the upgrade, and `Uncertain` tickets it opened under the old token cannot be reconciled through it.

**W-3. The worker did not start on current Node, and on older Node it would have run an ordinary contextified realm.** *Confirmed and fixed.* Node 24 rejects `--no-expose-wasm` because its V8 no longer has the flag, so no worker started. Node before 22.8 (or 20.18 on the 20 line) has no `vm.constants.DONT_CONTEXTIFY`, and `vm.createContext(undefined, …)` then builds an ordinary contextified realm; the lockdown happened to throw on every job there, which kept it closed by accident. The flag is gone (on Node 20.16 and 24.22.3, `--jitless` alone leaves no `WebAssembly` global), and `context.cjs` now exits before signalling readiness if `DONT_CONTEXTIFY` is missing or `WebAssembly` is reachable. Tests: `tooth_check_toolchain_only_refuses_a_node_without_dont_contextify` (Node 20.16) and, in `scripts/worker-context.test.cjs`, `a runtime that leaves WebAssembly reachable is refused before it is ready`.

**W-4. The broker did not build on macOS, and its stale-socket probe would have been wrong there.** *Fixed.* `unix::bind` probed an existing socket with `SOCK_NONBLOCK | SOCK_CLOEXEC`, which Darwin's `socket(2)` does not accept. Porting the flags alone would not have been safe: BSD-derived kernels refuse a connect to a listener whose accept queue is full with `ECONNREFUSED`, the error a dead listener gives, so a busy broker's socket would have been taken for stale and replaced. The C-4 probe is now compiled for Linux only; elsewhere `bind` never replaces an existing socket and asks the operator to remove a stale one. Three helpers in `crates/keygate/tests/cli.rs` used only by Linux tests are compiled only there. Test: `bind_keeps_existing_socket_where_busy_and_stale_look_alike` (macOS).
